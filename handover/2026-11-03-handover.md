### Design (agreed direction — implement this shape)

- ruke-browser must NOT depend on ruke-websearch. Define a minimal payload
  in ruke-browser (e.g. `struct TurnAffinity { hosts: Vec<String> }` —
  lowercase literal hosts, first-seen order): ruke-server computes it from
  `ruke_websearch::task_scope::scope_hosts` when `is_enforceable_scope`.
- Registration: extend the engine boundary — either a new
  `begin_turn_with_affinity(session,turn,Option<TurnAffinity>)` or a method
  called right after `begin_turn` in run_tool_loop; store keyed by TurnKey
  inside BrowserRuntime, cleared at end_turn/guard-drop (mirror the
  turn-token lifecycle in engine.rs).
- **Separate checks, two places, in this order BEFORE the page is touched:**
  1. **Affinity (task scope, turn-scoped, ephemeral):** for
     NavigateTabUrl always; for TabNew when `url` is Some. Destination host
     match: `dest == scope_host` OR `dest` is a subdomain (`dest.ends_with(
     ".{scope_host}")`), computed on PSL registrable host with literal-host
     fallback (IPs). HUMAN_TURN_ID ⇒ skip (human control). No affinity
     registered (scope None / non-enforceable) ⇒ no check. Off-scope hop ⇒
     NOT a silent deny: park a ONE-SHOT human approval card naming the exact
     destination + that it is outside the task's site scope; accept = narrow
     per-hop authorization for THIS action only (never persisted, never
     blanket); decline/timeout/no-panel ⇒ typed refusal. (This implements
     the "auth/payment hops = narrow authorization" clause; the scope
     guidance already lists authorizedHosts as pre-authorized.)
  2. **Facet authority gate on the DESTINATION url (fixes #8):** change the
     dispatch path so NavigateTabUrl calls an
     `apply_gate_url(key, tab_id, destination_url, facet, label)` variant
     (refactor apply_gate to share gate_on_host; keep the old source-based
     behavior for every other command — Back/Forward/Reload destinations are
     history-current, unknowable-in-advance page navigations).
- Documented limitation (report honestly in P7.5): link-click/form-submit/JS
  navigations have no pre-knowable destination; enforcement there remains
  post-landing (registry url update) + the model-facing scope guidance.
  "A check after an unauthorized page has loaded is insufficient" is fixed
  WHERE a destination is knowable (nav/tab-new/typed URL), not claimed
  universally.
- Deterministic tests: ruke-browser affinity matcher (exact/subdomain/IP
  literal/case/authorization one-shot/no-persist), gate-for-parity test that
  NavigateTabUrl gates the destination, human-turn skip, no-affinity skip,
  end_turn clears the registration. No golden/fixture impact (verify by
  re-running suites; counts should move ONLY by the new tests).
